# Talkvyn database

This workspace package owns the PostgreSQL contract, Prisma ORM 8 client, and database commands. The repository root `compose.dev.yaml` provides local PostgreSQL, Redis, and Mailpit services. Production Compose configuration belongs under `deploy/`. Keep database models in focused files under `src/prisma/schema/`; `contract.prisma` is generated by stitching those files together.

## Local setup

Set `DATABASE_URL` in the repository root `.env` file. For the local PostgreSQL container, the example value is:

```env
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/talkvyn?schema=public
```

Start PostgreSQL, Redis, and Mailpit:

```sh
pnpm services:up
```

Initialize the empty PostgreSQL database:

```sh
pnpm --filter @talkvyn/database db:init
```

Redis is available at `redis://localhost:6379`. Mailpit captures SMTP on `localhost:1025`; view messages at <http://localhost:8025>. Both ports bind to loopback for local development.

## Schema workflow

Edit the relevant file under `src/prisma/schema/`, then emit the runtime contract and push it to the development database:

```sh
pnpm --filter @talkvyn/database contract:emit
pnpm --filter @talkvyn/database db:push
pnpm --filter @talkvyn/database db:verify
```

`contract.prisma`, `contract.json`, and `contract.d.ts` are generated from the modular schema and are committed. The initial staff, permission, and session models live together in `schema/identity.prisma`; future modules can have their own schema files. Staff receive permissions through one role; sessions store only token hashes and support expiry and revocation. The runtime client is exported as `db` from `@talkvyn/database`; close it during application shutdown with `db.close()`.

`db:push` uses Prisma 8's `prisma db update` command to reconcile the development database directly with the contract. It does not create a migration. This is the Prisma 8 equivalent of the Prisma 7 `db push` workflow. Migration commands remain available for environments that need checked-in migration history.

## Staff bootstrap seed

Set `STAFF_BOOTSTRAP_NAME`, `STAFF_BOOTSTRAP_EMAIL`, and `STAFF_BOOTSTRAP_PASSWORD` in the root `.env`, then run:

```sh
pnpm --filter @talkvyn/database seed:staff
```

The idempotent seed creates the built-in staff roles and staff CRUD permissions and provisions the initial administrator only when that email is not already present. It hashes the password before storage and does not print it.

Stop the local services with `pnpm services:down`. Their named volumes keep database data between restarts.
